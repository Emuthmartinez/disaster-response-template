# banned-patterns.txt
#
# One extended-regex (grep -E / POSIX ERE) pattern per non-comment, non-blank
# line. Consumed by scripts/content-audit/run.sh.
#
# Three kinds of lines:
#   1. Plain pattern             -> HARD-BANNED, case-INsensitive. Must not
#                                    match ANYWHERE in the tree (no file is
#                                    exempt, including README* and
#                                    docs/standup-guide.md).
#   2. "CONTEXT:<pattern>"       -> CONTEXT-BANNED, case-insensitive. Allowed
#                                    only inside the fixed allowlist the
#                                    script hard-codes (README.md,
#                                    README.es.md, docs/standup-guide.md),
#                                    where it is the template's own
#                                    origin-story prose. Banned everywhere
#                                    else (code, config, other docs).
#   3. "CASESENSITIVE:<pattern>" -> HARD-BANNED, case-SENSITIVE (exact case
#                                    only). Use this for an identifier that
#                                    overlaps a CONTEXT-banned prose word in
#                                    its lowercase/titlecase form (e.g. a
#                                    real ALLCAPS constant vs. the same word
#                                    allowed in README prose) — without this,
#                                    a case-insensitive hard ban would also
#                                    swallow the allowed prose use.
#
# Lines are matched with grep -E; a leading "-" in a pattern is safe because
# run.sh always reads patterns via grep -f, never as a shell argument.
#
# Keep this file append-only-ish: if you widen a pattern, re-run run.sh and
# confirm you haven't opened a hole, and check docs/DESIGN.md /
# docs/architecture.md for legitimate generic infra terms (e.g. plain "mapa",
# "example.org") that must keep matching NOTHING here.
#
# ---------------------------------------------------------------------------
# Private overlay mechanism
# ---------------------------------------------------------------------------
# This PUBLIC file intentionally contains only class-generic pattern SHAPES
# (secret formats, any-public-IPv4, personal-email providers, phone-number
# shapes, payment/social link hosts) — never a real, deployment-specific
# literal (no real IP, hostname, email, phone number, third-party ID/slug,
# domain, handle, brand/partner name, or exact coordinate). Shipping the real
# literals here would defeat the purpose of the scanner: anyone reading a
# public template would learn exactly what infra/identities/locations a real
# deployment used.
#
# Maintainers who also want to hard-ban their OWN deployment-specific
# literals (the origin deployment this template was extracted from, or any
# fork's real infra) keep those in a sibling file:
#
#   scripts/content-audit/banned-patterns.local.txt
#
# That file is gitignored (see .gitignore) and never published. run.sh loads
# it automatically when present, using the exact same
# plain/CONTEXT:/CASESENSITIVE: syntax as this file. If it's missing, run.sh
# just runs with the generic patterns below — nothing breaks. The overlay
# for THIS template's own origin deployment stays with the maintainer and is
# not part of the published repo.

# ---------------------------------------------------------------------------
# Hard-banned: phone-number shape (E.164-ish, 9+ digits after a leading +).
# ---------------------------------------------------------------------------
[+][0-9]{9,}

# ---------------------------------------------------------------------------
# Hard-banned: Google Analytics measurement ID shape. Requires a digit
# somewhere in the id (real measurement IDs always have one) so the common
# doc placeholder "G-XXXXXXXXXX" (all letters, no digits) keeps matching
# NOTHING here — it's not a real id.
# ---------------------------------------------------------------------------
\bG-[A-Z0-9]{2,}[0-9][A-Z0-9]{2,}\b

# ---------------------------------------------------------------------------
# Hard-banned: social/payment/messaging link hosts with a fixed recipient or
# invite baked in. A default pointing at any one destination (someone's
# Discord, GoFundMe, Stripe Payment Link, PayPal checkout, or WhatsApp
# number) must never ship as a default in a public template.
# ---------------------------------------------------------------------------
discord\.gg/
gofund\.me/
gofundme\.com/
buy\.stripe\.com/[A-Za-z0-9]
paypal\.com/ncp/payment/
wa\.me/[A-Za-z0-9]+
chat\.whatsapp\.com

# ---------------------------------------------------------------------------
# Hard-banned: generic secret shapes
# ---------------------------------------------------------------------------
# AWS access key ID (all known prefixes)
\b(A3T[A-Z0-9]|AKIA|AGPA|AIDA|AROA|AIPA|ANPA|ANVA|ASIA|ASCA|APKA)[A-Z0-9]{16}\b
# AWS-style secret assigned to an aws_secret_access_key-shaped variable
aws_secret_access_key[[:space:]]*[:=][[:space:]]*["']?[A-Za-z0-9/+=]{40}
# PEM/private-key headers of any kind
-----BEGIN[[:space:]]?(RSA|EC|DSA|OPENSSH|ENCRYPTED|PGP)?[[:space:]]?PRIVATE KEY-----
# JWT-looking three-segment base64url token
eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}
# 32+ hex chars assigned to a *_SECRET / *_KEY / *_APIKEY-shaped variable
[A-Za-z_][A-Za-z0-9_]*(SECRET|_KEY|APIKEY)[A-Za-z0-9_]*[[:space:]]*[:=][[:space:]]*["']?[0-9a-fA-F]{32,}
